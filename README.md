## Зорилго

Энэ лабораторийн ажлаар Mockito ашиглан Java кодын тест бичиж үзсэн. Тест бичихдээ mock объект ашиглан гаднын хамаарлуудыг орлуулж, тухайн код зөв ажиллаж байгаа эсэхийг шалгасан. Мөн кодонд зориудаар өөрчлөлт оруулж, тестүүд алдааг илрүүлж чадаж байгаа эсэхийг туршсан.

## Хэсэг A — Тестүүд

`CourseRegistrationServiceTest` класс дотор A1–A8 шаардлагуудын дагуу тестүүд бичсэн. A8 дээр параметржүүлсэн тест ашигласан бөгөөд 3 өөр нөхцөлийг шалгасан. Тиймээс нийт 10 тест ажиллаж байгаа.

Тестүүдийг ажиллуулахад бүгд амжилттай болсон. Үүнийг `results/mvn-test.txt` файл дахь `Tests run: 10, Failures: 0, Errors: 0` болон `BUILD SUCCESS` үр дүнгээс харж болно.

### A8 дахь lenient()

A8 тестийн гурван нөхцөлд өөр өөр stub ашигласан. Зарим нөхцөлд тухайн параметрт хэрэггүй stub үлдэж байсан учраас Mockito-ийн `UnnecessaryStubbingException` алдаа гарахаас сэргийлж зөвхөн эдгээр нөхцөлт stub-уудад `lenient()` ашигласан.

## Хэсэг B — Мини мутаци

Тестүүд кодын алдааг илрүүлж чадаж байгаа эсэхийг шалгахын тулд 3 өөрчлөлт хийж туршсан. Гарсан үр дүнг `results/` хавтас дахь Maven-ийн бодит гаралтаас авсан.

| Мутант | Хийсэн өөрчлөлт | Унасан тестүүд |
|---|---|---|
| 1 | Идэвхгүй оюутны шалгалтыг комментолсон | `inactiveStudent_returnsErrorWithoutEmailInteraction`, `registrationErrorCases_returnExpectedError[2]` |
| 2 | Бүртгэл хадгалах `saveRegistration()` дуудлагыг комментолсон | `activeStudentWithCompletedPrerequisites_registersAndSendsEmail`, `emailFailure_doesNotCancelSuccessfulRegistration` |
| 3 | `courseId == null` шалгалтыг хассан | `nullStudentIdOrCourseId_throwsWithoutDependencyInteraction` |

Туршилтын үр дүнд эхний болон хоёр дахь мутант дээр тус бүр 2 тест, гурав дахь мутант дээр 1 тест унасан. Гурван өөрчлөлтийг бүгдийг нь тестүүд илрүүлсэн.

Мутацийн шалгалтын дараа эх кодыг буцааж сэргээж, тестийг дахин ажиллуулсан. Эцсийн шалгалтаар 10 тест бүгд амжилттай болсон.

## Дүгнэлт

Энэ лабораторийн ажлаар Mockito ашиглан тест бичиж, хэрхэн ажилладгийг нь туршиж үзлээ. Мөн кодонд зориудаар өөрчлөлт оруулж, бичсэн тестүүд алдааг илрүүлж чадаж байгаа эсэхийг шалгасан.

Mock болон fake хоёрын ялгааг ойлгож авсан. Mock нь тестийн үед хамааралтай объектыг орлуулж, үйлдлийг нь тохируулахад ашиглагддаг бол fake нь бодит интерфейсийг хялбаршуулсан байдлаар хэрэгжүүлдэг объект юм.

Мөн бүх зүйлийг mock хийх шаардлагагүй гэдгийг ойлгосон. Энгийн өгөгдлийн объект болон тестийн логикийг шаардлагагүйгээр mock хийх нь тестийг ойлгомжгүй болгож болно. `verify`-г хэт их ашиглавал тест кодын дотоод ажиллагаанаас хамааралтай болж, код өөрчлөгдөхөд тест эвдрэх эрсдэлтэй.
